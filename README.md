## plan-executor-agent

**作者：** zhou0928
**版本：** 0.2.1
**类型：** agent-strategy

### 简介

面向 Dify 的 **Plan-and-Execute（先规划再执行）** Agent 策略。模型先生成结构化的分步骤计划，再以工具感知的方式逐步执行。步骤失败或结果偏离计划时自动重规划。支持流式输出、并行步骤执行、文件输入和执行元数据上报。

### 功能特性

- **先规划后执行**：调用任何工具之前，模型先生成结构化计划
- **工具感知**：执行器只使用节点中可用、且匹配 `allowed_tools` 白名单的工具
- **自动重规划**：计划执行失败或工具报错时，最多重规划 `max_replan` 次（非法计划独立预算）
- **失败归一化**：工具调用异常、推理 LLM 失败统一转为步骤错误并触发重规划；规划层失败（模型不可用等）则优雅退出并返回尾单
- **流式输出**：最终答案实时流式返回；`verbose` 打开时中间计划与步骤详情一并流出（会混入回复正文，见「已知限制与调参」）
- **并行执行**：设置 `max_parallel_steps` 可并行执行相互独立的步骤（默认 1，串行）
- **文件输入**：通过 `files` 参数传入图片，附加到每次 LLM 调用
- **执行元数据**：token 用量累计并上报到 Dify 用量面板

### 安装

1. 在 Dify 工作区安装插件（Agent 策略分类）。
2. 在 Chatflow / Workflow 中添加 **Agent** 节点，选择 **Plan-Executor Agent**。

### 参数说明

| 参数 | 说明 | 默认值 |
|------|------|--------|
| `model` | 规划与执行使用的 LLM 供应商及模型 | — |
| `query` | 用户问题 | — |
| `tools` | 可供执行器使用的工具 | — |
| `allowed_tools` | 可选，逗号分隔的工具名称白名单 | 全部 |
| `context` | 追加到用户消息中的额外上下文 | — |
| `files` | 可选，附加到每次 LLM 调用的图片文件 | — |
| `instruction` | 可选，追加到规划提示词中的额外指令 | — |
| `max_steps` | 每个计划的最大步骤数 | 20 |
| `max_replan` | 计划有效但执行失败时的最大重规划次数 | 2 |
| `max_invalid_plan` | 计划非法时的最大重规划次数（独立预算） | 2 |
| `max_parallel_steps` | 独立步骤并行度（1 为串行） | 1 |
| `planning_prompt` | 可选，自定义规划提示词 | 默认 |
| `output_variable` | 保存答案的工作流变量名 | `output` |
| `max_result_chars` | 工具/检索结果截断长度（保头尾，0 不限制） | 8000 |
| `max_execution_seconds` | 墙钟预算：超时后不再开新步骤，用已完成结果作答（0 关闭） | 480 |
| `verbose` | 是否流式输出中间计划与步骤详情 | 否 |

### 使用示例

例如问题 "对比各地区季度营收趋势" 会生成类似计划：

1. 获取各地区营收数据
2. 按季度聚合
3. 对比趋势并总结

每个步骤使用可用工具执行；失败时触发重规划而非直接停止。最终答案输出到 `output_variable`（默认 `answer`）。

### 已知限制与调参

- **单步结果长度**：工具或检索结果超过 `max_result_chars` 会被截断（保留头尾并标注省略字符数），设 0 关闭。这是控制 token 成本的主要旋钮。
- **执行时间预算 ≠ 生成长度**：守护进程的 `PLUGIN_MAX_EXECUTION_TIMEOUT`（默认 600 秒）到点会杀掉整次调用、丢弃全部结果。`max_execution_seconds` 默认 480，留出收尾余量；超预算时返回已完成部分而不是被杀。单次调用的长度由模型自身的最大生成 token 决定（ollama 为 `num_predict`）——本地慢模型单次可产出上万 token、耗时数分钟，只调大预算无效，需同时限制生成长度或调大守护进程上限。
- **历史只进规划**：多轮历史随「规划 / 最终作答」下发，逐步执行不重发，避免长会话按步数倍增 token。
- **文件产物**：工具产出的二进制/链接结果会作为节点文件输出（blob → 文件，image_link → 图片，link → 链接）；文本渲染里只留 `[blob] 文件名 (大小)` 占位，不会把 base64 灌进答案。
- **`verbose` 与干净回复互斥**：实测 Dify 1.17.1 下「直接回复」节点引用节点 `answer` 变量不会流式输出（回复为空），只能用 `.text`；而 `.text` 在 `verbose=true` 时包含计划与步骤文本。要干净回复请保持 `verbose=false`，过程看节点日志面板。
- **`binary_link` 兼容**：Dify 1.17 起 API 会下发 `binary_link`，而 `dify_plugin` 0.9/0.10 枚举中无此值。插件本身按字符串匹配、未知类型不报错，但 SDK 解析该消息会失败（例如内置 webscraper 遇到这类输出），需等 SDK 或对齐版本。
- **模型失败**：规划层失败会输出 `[计划执行 Agent] 模型调用失败（规划层）：…` 并写入空答案；上游配额/鉴权错误原样透出。

### 隐私

详见 [PRIVACY.md](./PRIVACY.md)。本插件不收集个人数据，仅将你的问题、上下文、工具与文件转发给节点中选定的 LLM 模型。
